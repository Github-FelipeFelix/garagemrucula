## Isolamento deste projeto — regra dura do Felipe

**Este projeto é o `garagemrucula`.** Mora em `Área de Trabalho\Projetos\garagemrucula`, e a sessão do
Claude nasce dentro desta pasta. Para abrir: digite **`garagem`** no Git Bash ou no PowerShell.

**Uma sessão trabalha um projeto só.** Não se lê arquivo de outro projeto, nem o transcript
dele, nem a lista do que existe lá. (Os nomes dos outros projetos ficam só na configuração local do hook — este arquivo é público.)

**Isto é barreira, não recomendação.** `.claude/hooks/` roda em toda chamada de ferramenta e
**bloqueia** (exit 2) qualquer caminho apontando para outro projeto — inclusive por comando de
shell, que é por onde a regra de permissão do `deny` não alcança. Se bloquear, **o bloqueio é a
resposta**: não reformule o comando para passar por fora. Se a informação só existe em outro
projeto, ela é para ser vista numa sessão aberta **naquela** pasta — avise o Felipe.

**A memória deste projeto mora em `garagemrucula/memory`,** apontada por caminho absoluto no
`.claude/settings.local.json`. Caminho relativo (`./memory`) é descartado em silêncio pelo
Claude Code, que valida com `path.isAbsolute()` — sem aviso e sem erro, a memória vai parar no
caminho global e se perde quando a pasta muda de lugar. Foi o que deixou 123 memórias órfãs (de vários projetos) até
12/08/2026.

**Por que tudo isso existe:** o Felipe tem vários projetos e sempre teve problema de memória e
contexto se misturando entre eles. Em 07/08/2026 separou tudo por pasta; em 12/08/2026, depois
de uma sessão de um projeto rodar por cima da de outro, a separação deixou de depender de boa
vontade e virou barreira do harness. Palavras dele: *"se não, não faz sentido eu dividir os
projetos por pasta"*.
